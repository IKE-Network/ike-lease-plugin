= IKE Working-Set Leases — IntelliJ Plugin

The third enforcement arm of the working-set lease design
(`dev-working-set-lease` in ike-lab-documents; tracked in
`IKE-Network/ike-issues#1002`). The other two — the lease protocol in
`~/ike-dev/scripts/lease.sh` and the Claude `PreToolUse` fence — are
already in force.

== What it does

Opening a project *is* the acquisition gesture. There is no separate
claim step to remember.

[cols="1,3", options="header"]
|===
| Lease state on open | Behaviour

| free or expired
| acquired silently, balloon confirms

| held live by another machine
| takeover dialog — take over, or continue read-only

| fenced while open (epoch advanced elsewhere)
| save all documents, notify, close the project
|===

Closing a project releases its lease, so the next machine to open it
acquires in silence rather than meeting a dialog.

The protocol itself is *not* re-implemented here: every operation shells
out to `scripts/lease.sh` through `LeaseCli`. A fencing system whose two
halves disagree about epochs or staleness is worse than one with no
fencing at all, so there is exactly one implementation.

== Building — Maven, not Gradle

JetBrains' supported toolchain is Gradle, and what it buys is mostly
ceremony this plugin does not need: SDK download, a `runIde` sandbox, the
Marketplace verifier, signing and publishing. This plugin touches only
core platform APIs, will never see the Marketplace, and a plugin
distribution is just a zip with a jar under `lib/`. Maven covers that, and
keeps one build tool in the house.

[source,bash]
----
mvn package
----

Nothing to install first: the build resolves the IntelliJ platform from
JetBrains' own Maven repository. The result,
`target/ike-lease-plugin-<version>.zip`, installs through
*Settings → Plugins → ⚙ → Install Plugin from Disk*, or by unzipping into
the IDE's `plugins/` directory. Either way, restart the IDE.

Releases are published to the internal Nexus (`ike-staging`, inherited
from `ike-base-parent`) and attached to the GitHub release. Never to Maven
Central: the parent's JReleaser configuration is bound to no lifecycle
phase, so inheriting it carries no obligation to publish anywhere public,
and an IDE plugin has no business on Central.

=== Where the platform artifacts come from

Five published artifacts, all from JetBrains' repository, all `provided`:

[cols="1,3", options="header"]
|===
| Artifact | What this plugin takes from it

| `platform:core`
| `Project`, `ApplicationManager`, `Service`, `FileDocumentManager`,
  `ProgressManager`, `Task`, `ProgressIndicator`

| `platform:util`         | `Disposable`
| `platform:project-model`| `ProjectManager`, `ProjectManagerListener`
| `platform:ide`          | `Messages`
| `platform:ide-core`     | `NotificationGroupManager`, `NotificationType`
|===

Both `intellij-repository/releases` and `intellij-dependencies` are
declared, because the platform's own transitive dependencies
(`intellij-deps-fastutil` and friends) live in the second; without it the
resolver fails on those rather than on the platform jars, which makes the
failure look like the wrong problem.

This replaced `install-idea-sdk.sh`, which copied eight jars out of the
locally installed IDE under the synthetic groupId
`com.jetbrains.intellij.local`. That script existed on the belief that
JetBrains published too thin a slice to build against — `platform:core`
has no `Disposable`, no `ProjectManager`, no `Messages`. The belief came
from examining only `core`; those classes are published, in `util`,
`project-model` and `ide`. The bucket serves no directory listing, which
is why the right combination went unfound rather than being unavailable.

The script also made the build unreproducible anywhere without IntelliJ
installed — which is every CI agent — so it had to go regardless.

`system`-scoped dependencies pointing straight at the IDE were the other
rejected route; Maven 4 has retired that scope.

== Status — working, takeover verified

Installed into IntelliJ IDEA Ultimate 2026.2.1 (IU-262.9437.185) and
exercised end to end on 2026-08-13:

* the plugin loaded, and opening projects acquired their leases — three
  open projects, three lease records, no interaction needed;
* a forced takeover from the other machine's command line was noticed by
  the watcher, which saved documents, posted the balloon, and closed the
  project;
* nothing in the plugin threw.

Installed on both machines and exercised IDE-to-IDE on 2026-08-13: the
Studio's plugin took `ike-komet-wsr`, and the MacBook closed it within
five seconds of the record arriving.

Two defects that run exposed, both fixed. `StartupActivity` is deprecated
— the platform logged "Migrate … to ProjectActivity" on every project
open — so the watcher is now started from `projectOpened` instead, and
the class is gone. Its replacement is a Kotlin coroutine interface that
Java cannot implement cleanly, and the watcher is application-level and
idempotent, so driving it from the first project open is equivalent.

More seriously, *nothing renewed a lease while a project sat open*. A
project open for twenty-nine minutes without edits let its ten-minute
lease lapse, and the other machine then took it **silently** — an expired
lease needs no permission, so the takeover dialog that protects live work
never appeared. Renewal is the holder's job in this model, and the holder
was not doing it. The watcher now sweeps every minute and re-asserts the
lease of every open project (the lease script itself only rewrites at
half-life, so the sweep is nearly free). Verified: an idle open project
renewed at the five-minute mark and holds its lease indefinitely.

Propagation of the takeover took about two and a half minutes in that
run, against roughly five seconds when measured in isolation: Syncthing
was mid-scan of the whole 42,000-file folder. The lease is delivered
promptly *when the sync layer is idle*, and the design should not assume
better.

== Open decisions

* *Where this lives.* A plain directory under `~/ike-dev` today — no git
  repo, no remote, no cascade registration. Whether it becomes its own
  repo (`ike-lease-plugin`, matching the artifact-id == repo ==
  directory convention) is unsettled.
* *Nexus.* The IDE jars are not on Maven Central; JetBrains runs its own
  repository. If CI ever builds this plugin, proxy JetBrains'
  repositories through Nexus rather than uploading IDE jars into it —
  IntelliJ IDEA *Ultimate* is commercial software, and hosting its jars
  is redistribution. A proxy caches without that question arising.

== Testing the takeover end to end

With the plugin installed on both machines, open the same working set on
each in turn. The second machine should raise the takeover dialog; on
confirming, the first should save, notify, and close within a few seconds
— the delay being the lease record's propagation, not any
machine-to-machine call.

The same protocol is exercisable from the command line at any time:

[source,bash]
----
~/ike-dev/scripts/lease.sh list
~/ike-dev/scripts/lease.sh status ike-komet-wsr
~/ike-dev/scripts/lease.sh acquire ike-komet-wsr --force
----
