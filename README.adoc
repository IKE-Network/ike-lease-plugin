= IKE Working-Set Leases

The working-set lease machinery of the multi-machine development fabric
(`dev-working-set-lease` in ike-lab-documents; delivered under
`IKE-Network/ike-issues#1002`): one writer at a time per working set
under `~/ike-dev`, with the synced lease record as both grant and bus.
Two Maven modules, one reactor (artifact `network.ike:ike-lease`):

[cols="1,3", options="header"]
|===
| Module | What it is

| `ike-lease-core`
| **The canonical lease protocol** (`LeaseProtocol` — verbs, epoch
  fencing, TTL staleness, reconcile-on-read, confirmed acquisition,
  ref stamps) plus everything decision-shaped around it: git-state
  materialization (`Materializer`), root ref alignment (`RefAligner` /
  `RefStamper`, ike-issues#1069), the origin manifest
  (`scripts/origins.conf` → `OriginManifest`), the reconciliation
  daemon (`LeaseDaemon`, ike-issues#1006), and the headless CLIs
  (`LeaseProtocolCli`, `MaterializeCli`). IntelliJ-free by
  construction — `module-info` imports nothing from `com.intellij`.

| `ike-lease-plugin`
| The IntelliJ host: a thin adapter contributing the trigger (the open
  gesture), the interaction surface (dialogs, balloons, progress), and
  IDE cleanup (VCS-mapping refresh). `LeaseProjectListener` +
  `LeaseWatcher` acquire/renew, `MaterializeOnOpen` materializes and
  aligns after the confirmed acquisition, and `SiblingPrePushGuard`
  refuses pushes from a sibling working set to a non-local remote
  (ike-issues#992).
|===

`~/ike-dev/scripts/lease.sh` is a *wrapper*: it finds the newest core
jar and execs `LeaseProtocolCli` (ike-issues#1067). Every caller — the
Claude fence, the operator, this plugin — runs the same single
implementation, because a fencing system whose halves disagree about
epochs or staleness is worse than no fencing at all. The equivalence
suite in `ike-lease-core` holds the port byte-for-byte against a frozen
copy of the shell v2 it replaced.

== What the IDE host does

Opening a project *is* the acquisition gesture — confirmed against the
sync-propagation race (write, wait out the settle window, re-read).
There is no separate claim step to remember.

[cols="1,3", options="header"]
|===
| Lease state on open | Behaviour

| free or expired
| acquired silently (confirmed), balloon confirms

| held live by another machine
| takeover dialog — take over, or continue read-only

| fenced while open (epoch advanced elsewhere)
| save all documents, notify, close the project
|===

After the confirmed acquisition the open gesture also repairs git
state, tree-untouched in both directions:

* a **bare tree** (`.git` never syncs) is *materialized* — roots from
  the synced origin manifest, siblings wired parent-first to their
  local parent member paths;
* **stale refs** are *aligned* to the `stamp:` lines the previous
  holder wrote into the lease record at renew/release — fetch, move
  the branch ref and HEAD, `reset --mixed`; the tip wins over a stale
  stamp, unpushed history is reported and never chased, and local-only
  divergence refuses the move rather than orphaning commits.

Closing a project releases its lease, so the next machine to open it
acquires in silence rather than meeting a dialog.

== Installing

[source,bash]
----
./mvnw verify
----

The result, `ike-lease-plugin/target/ike-lease-plugin-<version>.zip`,
carries **both jars** under `ike-lease-plugin/lib/` — the IDE adapter
and the core. Unzip it into the IDE's `plugins/` directory (or use
*Settings → Plugins → ⚙ → Install Plugin from Disk*) and restart the
IDE. Installing the zip is also what provisions the command line:
`lease.sh` and `lease-daemon.sh` glob the installed `lib/` for the
core jar, so the IDE install serves the headless CLIs and the launchd
daemon too. `scripts/setup-machine.sh` performs the install as part of
bringing a machine into the fleet.

== Building — Maven, not Gradle

JetBrains' supported toolchain is Gradle, and what it buys is mostly
ceremony this plugin does not need: SDK download, a `runIde` sandbox,
the Marketplace verifier, signing and publishing. This plugin touches
only core platform APIs, will never see the Marketplace, and a plugin
distribution is just a zip with jars under `lib/`. Maven covers that,
and keeps one build tool in the house.

=== Releasing

Two steps, both from a clean `main` (a milestone `ike-lease v<N>` must
exist on ike-issues):

[source,bash]
----
./mvnw ike:release-draft      # prints the plan; changes nothing
op run --env-file ~/.config/ike/release.env -- ./mvnw ike:release-publish -B
----

Releases go to the internal Nexus (`ike-staging`, inherited from
`ike-base-parent`) and to the GitHub release. *Never to Maven Central.*
Note that this takes a deliberate override: `ike-base-parent` sets
`ike.publishToCentral` to `true`, so inheriting it opts a repository
into Central, and `<properties>` here sets it back to `false`. These
goals read POM *properties* — the same names in a plugin
`<configuration>` block are reported unknown and silently do nothing.

An IDE plugin has no business on Central, and its dependencies are
JetBrains platform artifacts that nothing outside this build resolves.

=== Where the platform artifacts come from

Five published artifacts, all from JetBrains' repository, all
`provided`, all confined to the `ike-lease-plugin` module:

[cols="1,3", options="header"]
|===
| Artifact | What the IDE host takes from it

| `platform:core`
| `Project`, `ApplicationManager`, `Service`, `FileDocumentManager`,
  `ProgressManager`, `Task`, `ProgressIndicator`

| `platform:util`         | `Disposable`
| `platform:project-model`| `ProjectManager`, `ProjectManagerListener`
| `platform:ide`          | `Messages`
| `platform:ide-core`     | `NotificationGroupManager`, `NotificationType`
|===

Both `intellij-repository/releases` and `intellij-dependencies` are
declared (proxied through the internal Nexus), because the platform's
own transitive dependencies (`intellij-deps-fastutil` and friends)
live in the second; without it the resolver fails on those rather than
on the platform jars, which makes the failure look like the wrong
problem. The earlier `install-idea-sdk.sh` copy-jars-from-the-IDE
approach was falsified and deleted — the published slice is
sufficient; the classes thought missing live in `util`,
`project-model`, and `ide`.

== History

Field milestones, condensed (the full engineering narrative lives in
the design topic and the closed issues):

* *2026-08-13* — first install on two machines; IDE-to-IDE takeover
  verified both directions. Two defects found by the run and fixed:
  `StartupActivity` deprecation (watcher now starts from
  `projectOpened`) and the renewal gap — nothing renewed an idle open
  project's lease, so it silently expired; the watcher now sweeps
  every open project every 60 seconds.
* *2026-08-22* — materializer field-passed cross-machine
  (ike-issues#1057); protocol port flipped, `lease.sh` became the
  wrapper (#1067); daemon live on the fleet (#1006); ref alignment
  delivered and field-proven on all three machines (#1069). Released
  as `ike-lease` 5, installed fleet-wide; this repository is
  `IKE-Network/ike-lease-plugin`, per-machine installs via
  `setup-machine.sh`, no cascade registration by design.

One operational caveat that stays true: lease propagation is prompt
(seconds) *when the sync layer is idle*, and minutes when Syncthing is
mid-scan of the whole folder — the design does not assume better,
which is what the confirmed-acquisition settle window is for.

== Testing the takeover end to end

With the plugin installed on both machines, open the same working set
on each in turn. The second machine should raise the takeover dialog;
on confirming, the first should save, notify, and close within a few
seconds — the delay being the lease record's propagation, not any
machine-to-machine call.

The same protocol is exercisable from the command line at any time:

[source,bash]
----
~/ike-dev/scripts/lease.sh list
~/ike-dev/scripts/lease.sh status ike-komet-wsr
~/ike-dev/scripts/lease.sh acquire ike-komet-wsr --force
----
